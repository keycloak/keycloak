
[[_oid4vci_managing_credentials]]
=== Managing Issued Credentials

Before issuing credentials, administrators must configure an OID4VCI client scope and assign a verifiable credential to the user (see <<_oid4vci_user_setup, Creating a User Account>>). Once issued via the OID4VCI protocol, credentials can be viewed, managed, and revoked by administrators through the Admin Console or Admin REST API, or by users through the Account Console. This section explains how to manage the credential lifecycle and handle compromise scenarios.

==== Viewing Credential Entitlements

A credential entitlement represents a user's authorization to receive a specific type of Verifiable Credential. Administrators assign these entitlements before credentials can be issued.

To view a user's credential entitlements:

. In the Admin Console, click *Users* in the menu.
. Select the user.
. Click the *Verifiable Credentials* tab.

.Verifiable Credentials tab showing credential entitlements
image::images/oid4vci/screenshot-user-vc-tab.png[Verifiable Credentials tab on the user detail page, width=750]

The table lists each credential type assigned to the user. Use the kebab menu on each row to access available actions.

.Available actions for a credential entitlement
image::images/oid4vci/screenshot-user-verifiable-credentials-tab.png[Kebab menu showing available actions for a credential entitlement, width=750]

The following actions are available:

* *View Attributes* -- Shows the user attribute snapshot associated with this credential type.
* *View Issued Credentials* -- Opens a detail view of all credentials issued to the user for this type.
* *Update Credential* -- Refreshes the stored user attributes and increments the credential revision.
* *Revoke* -- Removes the credential entitlement and deletes all issued credential records for that user and credential type.
* *Send Credential Offer* -- Sends a credential offer to the user via email (requires the user to have an email address configured).

==== Viewing Issued Credentials

Each credential entitlement can have multiple issued credential records -- for example, when the credential is issued through independent authorization grants or wallet clients. Refreshing through an existing refresh token reuses its issued credential record.

To view individual issued credentials:

. Navigate to *Users* > select the user > *Verifiable Credentials* tab.
. Click the kebab menu on a credential entitlement row.
. Select *View Issued Credentials*.

.Issued credentials detail view
image::images/oid4vci/screenshot-user-issued-credentials-detail.png[Individual issued credentials showing id and issuedAt and expiresAt and walletClient and revision, width=750]

Each issued credential shows:

* *ID* -- The unique identifier of the issued credential record.
* *Issued At* -- When the credential was issued.
* *Expires At* -- When the credential record expires (based on the *Credential Lifetime* setting of the OID4VCI client scope).
* *Wallet Client* -- The OID4VCI client through which the credential was issued.
* *Revision* -- The credential revision number. An "outdated" label appears if the credential was issued with an older revision of the user's attributes.

==== Credential Revocation

===== Understanding Revocation in OID4VCI

{project_name} uses a two-tier revocation model for Verifiable Credentials:

* *Revoking an individual issued credential* -- Removes the specific credential record from the database. The wallet can no longer refresh this credential.
* *Revoking a credential type entitlement* -- Removes the user's authorization for that credential type and deletes all issued credential records for that user and type, preventing future issuance.

[IMPORTANT]
====
Revocation on the server side removes the database record and prevents future credential refresh. However, a Verifiable Credential already held by a wallet remains cryptographically valid until its `exp` (expiration) claim passes. There is currently no status list mechanism for verifiers to check whether a credential has been revoked on the server. To limit exposure from compromised credentials, configure a short *Credential Refresh Interval* (`vc.refresh_interval_in_seconds`).
====

===== Revoking Individual Issued Credentials

To revoke a specific issued credential through the Admin Console:

. Navigate to *Users* > select the user > *Verifiable Credentials* tab.
. Click the kebab menu on the credential entitlement row and select *View Issued Credentials*.
. Click *Revoke* on the specific issued credential.
. Confirm the revocation in the confirmation dialog.

.Revoking an individual issued credential
image::images/oid4vci/screenshot-user-issued-credential-revoke-confirm.png[Confirmation dialog when revoking an individual issued credential, width=650]

Using the Admin REST API:

[source,bash]
----
DELETE /admin/realms/{realm}/users/{userId}/vc/issued-credentials/{credentialId}
----

===== Revoking Credential Type Entitlements

Revoking a credential type entitlement removes the entitlement and *also deletes all issued credential records* for that user and credential type. This is a destructive operation that cannot be undone.

To revoke a user's entitlement to a credential type:

. Navigate to *Users* > select the user > *Verifiable Credentials* tab.
. Click the kebab menu on the credential entitlement row and select *Revoke*.
. Confirm the revocation.

.Revoking a credential type entitlement
image::images/oid4vci/screenshot-user-vc-entitlement-revoke-confirm.png[Confirmation dialog when revoking a credential type entitlement, width=650]

Using the Admin REST API:

[source,bash]
----
DELETE /admin/realms/{realm}/users/{userId}/vc/credentials/{scopeName}
----

==== Refresh Token and Credential Lifecycle

The OID4VCI credential lifecycle is governed by two time-based settings configured on the OID4VCI client scope:

* *Credential Lifetime* -- How long the credential record and its refresh token remain valid. Default *365 days* (31536000 seconds).
* *Credential Refresh Interval* -- How often the wallet must refresh the credential. This value sets the `exp` (expiration) claim in the issued VC JWT. Default *7 days* (604800 seconds), or the credential lifetime if shorter.

.Credential Lifetime and Refresh Interval settings on the OID4VCI client scope
image::images/oid4vci/screenshot-oid4vci-scope-lifetime-settings.png[OID4VCI client scope configuration showing Credential Lifetime and Credential Refresh Interval fields, width=750]

With the default settings, the credential refresh cycle works as follows:

. *Day 0* -- Wallet receives a credential (expires in 7 days) and a refresh token (expires in 365 days)
. *Day 7* -- The credential in the wallet is expired. The wallet automatically uses its refresh token to obtain a new access token from the token endpoint, then calls the credential endpoint to receive a freshly signed credential (expires Day 14).
. *Day 14, 21, 28...* -- The same refresh cycle repeats automatically. The user is never prompted to re-authenticate.
. *Day 365* -- The refresh token expires. The user must re-authenticate to obtain a new credential.

This design ensures the wallet always holds a recently signed credential (limiting exposure if a credential is compromised), while the user only needs to log in once per credential lifetime.

The credential lifecycle is also affected by the following events:

* *Refresh token revocation* -- When a wallet explicitly revokes a refresh token through the token revocation endpoint, {project_name} removes the corresponding issued credential record from the database. Ordinary user logout or removal of an individual session does not affect the refresh token or the issued credential record, since OID4VCI refresh tokens are session-independent. Setting the user's not-before policy (for example, through *Sign out all active sessions*) prevents further refresh but leaves the issued credential record stored as stale.
* *Credential entitlement revocation* -- When an administrator or user revokes the credential type entitlement, all issued credential records for that user and credential type are deleted. The wallet can no longer refresh the credential.

[WARNING]
====
Requesting an OID4VCI scope during login produces a refresh token whose lifetime is governed by the *Credential Lifetime* setting rather than the user session lifespan. Because this token remains valid after user logout, it must be stored securely within the wallet application.
====

[NOTE]
====
OID4VCI scope access tokens are purpose-locked exclusively to the {project_name} credential endpoint. Because their audience (`aud`) claim is set to the credential endpoint URL, they are blocked from accessing other {project_name} APIs, including the introspection, Admin REST, and Account REST APIs.
====

For details on configuring these settings, see <<_understanding_credential_lifetime_vs_refresh_interval, dedicated section>>.

==== Responding to Compromise

===== User Account Compromised

If a user account is compromised, follow these steps to revoke all issued credentials and prevent further issuance:

. *Disable the user account* -- Navigate to *Users* > select the user > toggle *Enabled* to *Off*. This prevents new logins.
. *Revoke active sessions* -- Navigate to *Users* > select the user > *Sessions* and click *Sign out all active sessions*. This sets the user's not-before policy and invalidates only that user's active tokens, including refresh tokens used for credential refresh.
+
.Session revocation
image::images/oid4vci/screenshot-user-sessions-revocation.png[Sessions revocation page, width=650]
. *Revoke credential entitlements* -- Navigate to *Users* > select the user > *Verifiable Credentials* tab. Revoke each credential type entitlement. This deletes all issued credential records and prevents any future credential issuance for this user.

[NOTE]
====
Verifiable Credentials already held by wallets remain cryptographically valid until their `exp` claim expires. Setting a short *Credential Refresh Interval* (`vc.refresh_interval_in_seconds`) limits the window of exposure. For example, a 24-hour refresh interval means a compromised credential becomes unusable within 24 hours of the session revocation, since the wallet cannot refresh it.
====

===== Client or Wallet Application Compromised

If a client application or wallet is compromised, follow these steps to prevent further use of credentials issued through that client. Credentials already held by wallets remain valid until their `exp` claim expires:

. *Disable the client* -- Navigate to *Clients* > select the compromised client > toggle *Enabled* to *Off*. This prevents all token operations, including refresh, through this client.
+
.Disabling a compromised client
image::images/oid4vci/screenshot-client-disable.png[Client settings page with Enabled toggle, width=650]
. All refreshes of existing credentials through this client become impossible.
. *Alternative*: Delete and re-create the client. Deleting a client automatically removes all issued credential records associated with it.

[NOTE]
====
There is currently no bulk API to revoke all credentials issued through a specific client. To revoke individual credentials, use the per-user Admin UI or REST API as described above. Each issued credential record shows the *Wallet Client* it was issued through, which helps identify affected credentials.
====

==== Self-Service Credential Management via the Account Console

In addition to administrator-managed credential operations, users can view and manage their own Verifiable Credentials through the {project_name} Account Console. This enables self-service workflows where users can monitor their issued credentials and revoke them if needed.

===== Prerequisites

The Account Console Verifiable Credentials page is available when all of the following conditions are met:

* The `oid4vc-vci` server feature is enabled.
* Verifiable Credentials are enabled at the realm level (in *Realm Settings*).
* The user has one of the following account roles:
** `manage-account` -- Grants full access, including viewing and revoking credentials.
** `view-verifiable-credentials` -- Grants read-only access to view credentials.
** `manage-verifiable-credentials` -- Grants access to view and revoke credentials.
* When using either Verifiable Credentials-specific role, add that role to the `account-console` client's scope mappings; these roles are not mapped there by default.

===== Viewing Credentials in the Account Console

Users can access their Verifiable Credentials by navigating to the *Verifiable Credentials* page in the Account Console sidebar.

.Verifiable Credentials page in the Account Console
image::images/oid4vci/screenshot-account-vc-page.png[Verifiable Credentials page in the Account Console, width=750]

The page lists each credential type assigned to the user, showing the credential scope name, creation date, and last updated date. Each credential row provides the following actions:

* *View Issued Credentials* -- Opens a modal showing all individual issued credentials for this credential type, including issuance date, expiration date, and wallet client information.
+
.Issued credentials modal in the Account Console
image::images/oid4vci/screenshot-account-issued-credentials-modal.png[Issued credentials modal showing individual credentials in the Account Console, width=750]

* *Issue to Wallet* -- Initiates a credential offer flow that allows the user to receive the credential in their wallet. For additional details about credential offer, see the <<_oid4vci_credential_offer_aia,dedicated documentation section>>.
* *Revoke* -- Revokes the credential type entitlement and deletes all issued credential records for that credential type. This action is only available to users with the `manage-account` or `manage-verifiable-credentials` role.

===== Revoking Credentials in the Account Console

Users with the appropriate role can revoke credentials at two levels:

* *Credential type entitlement* -- Click *Revoke* on the credential row in the main list. This removes the entitlement and deletes all issued credential records for that user and credential type.
* *Individual issued credential* -- Click *View Issued Credentials*, then click *Revoke* on the specific issued credential. This removes only that credential record from the database.

[NOTE]
====
The `view-verifiable-credentials` role provides read-only access. Users with this role can view their credentials and issued credential details but cannot revoke them. The *Revoke* action buttons are hidden for users without revocation permissions.
====

===== Account REST API Reference

The following endpoints are available under `/realms/{realm}/account` for user self-service credential management:

[cols="1,3,3",options="header"]
|===
| Method | Path | Description

| `GET`
| `/verifiable-credentials`
| List the user's credential type entitlements.

| `DELETE`
| `/verifiable-credentials/{scopeName}`
| Revoke a credential type entitlement.

| `GET`
| `/issued-verifiable-credentials`
| List all issued credentials for the user.

| `DELETE`
| `/issued-verifiable-credentials/{credentialId}`
| Revoke a specific issued credential.
|===

==== Admin REST API Reference

The following endpoints are available under `/admin/realms/{realm}/users/{userId}` for managing Verifiable Credentials:

[cols="1,3,3",options="header"]
|===
| Method | Path | Description

| `GET`
| `/vc/credentials`
| List the user's credential type entitlements.

| `POST`
| `/vc/credentials`
| Create a new credential type entitlement for the user.

| `PUT`
| `/vc/credentials/{scopeName}`
| Update a credential entitlement (refresh attributes, increment revision).

| `DELETE`
| `/vc/credentials/{scopeName}`
| Revoke a credential type entitlement.

| `GET`
| `/vc/issued-credentials`
| List all issued credentials for the user.

| `DELETE`
| `/vc/issued-credentials/{credentialId}`
| Revoke a specific issued credential.

| `PUT`
| `/vc/credentials/send-credential-offer`
| Send a credential offer to the user via email.
|===
