= User interface

== Login v1 theme removed

The legacy Login v1 theme based on PatternFly 3/4 has been deprecated for a long time and has been removed for this release.

= Administration

== Service account user ID available on client representation

The service account user ID is now included directly in the client representation as the `serviceAccountUserId` field.
This removes the need for a separate API call to discover the service account user, simplifying client administration and role mapping workflows.
The dedicated `GET /admin/realms/\{realm}/clients/\{id}/service-account-user` endpoint has been removed.
See the upgrading guide for migration details.

= Security and Standards

== Post-quantum WebAuthn signatures (experimental)

{project_name} introduces experimental support for `ML-DSA-44`, `ML-DSA-65`, and `ML-DSA-87` in WebAuthn policies.
Enable it with `--features=webauthn-ml-dsa`.
Using these algorithms requires a compatible browser, authenticator, and server cryptographic provider.
The default signature algorithms remain unchanged.

For requirements, see link:{adminguide_link}#_webauthn-pqc[Post-quantum signature algorithms] in the {adminguide_name}.

== PAR discovery respects the feature flag

When the `par` feature is disabled, OpenID Connect discovery no longer advertises the pushed authorization request endpoint, including its mTLS alias, or `require_pushed_authorization_requests`.
Discovery metadata is unchanged when PAR is enabled.

== SAML OneTimeUse condition enforced for identity brokering

When an external SAML identity provider issues an assertion with a `OneTimeUse` condition, {project_name} now rejects any later attempt to present the same assertion, as required by the SAML 2.0 specification.
This protects brokered logins against assertion replay, in particular in IdP-initiated flows where no `InResponseTo` binding is available.
How long a consumed assertion is remembered is bounded by the new *OneTimeUse maximum age* setting of the SAML identity provider, which defaults to 1 hour.
See the upgrading guide for details.

== Credential ID in credential update events

The `UPDATE_CREDENTIAL` events emitted by built-in required actions now carry the `credential_id` detail when a credential was created or updated in the {project_name} credential store, as the `REMOVE_CREDENTIAL` event already did. The detail is omitted when an external user-storage provider handles the update because there is no {project_name} credential ID to report.

= Themes

== Login and welcome UI upgraded to PatternFly 6

The built-in login theme is now `keycloak.v3`, based on PatternFly 6. The previous `keycloak.v2` login theme has been removed.
The welcome page shares the `keycloak.v3` login theme's layout, form controls, branding, and PatternFly 6 styles.

Realms that explicitly used `keycloak.v2` are migrated to `keycloak.v3` during upgrade. If you maintain a custom login theme based on `keycloak.v2`, or a custom welcome theme based on PatternFly 5, see the link:{upgradingguide_link}[{upgradingguide_name}] for migration steps.

== Login theme chrome macros

Custom login themes can override `header.ftl`, `aside.ftl`, `footer.ftl`, `alert.ftl`, and `language-selector.ftl` to customize brand content, a side panel for marketing or help text, the login-card footer, alerts, and the locale selector without replacing the full page layout.

== OID4VP verifier requests multiple credentials (experimental)

The OID4VP identity provider now requests credentials through the new *Requested credentials* section of the Admin Console, which lists the credentials, their accepted types, their trust material identity providers and the claim that identifies the user.
The Admin REST API stores this as a JSON document in the `requestedCredentials` configuration property.
It replaces the *DCQL Query*, *Principal Attribute*, *Trusted Issuer JWKS* and *Trust Material Identity Providers* settings, so existing OID4VP identity providers need to be configured again.
Each of their mappers now selects one of the requested credentials in its *Credential* setting.
Trusted issuer keys that were configured inline now go into a trust material identity provider.
An OID4VP identity provider is no longer a trust material identity provider itself, so replace references to it in other trust material settings with that trust material identity provider.

The DCQL query sent to the wallet is always built from the requested credentials and the claims that the identity provider mappers read.
If a mapper refers to a credential that is no longer requested, Keycloak logs a warning and treats the claim of the mapper as missing.
A user attribute mapper then removes its custom attribute at login, unless its sync mode is *Import*.

Credential sets express optional credentials and alternatives.
The credential holding the claim that identifies the user must be part of every option of at least one required credential set.
The user is linked by the presented type (`vct`) of that credential together with the claim, so a credential of another type with the same claim value does not sign in as that user.
Each accepted type of that credential therefore links its own identity.
The claim must be unique across all trusted issuers of a type, since any of them can issue a credential with that value.
Links to an OID4VP identity provider created by an earlier version no longer match and block the first broker login of their users, so remove them.
Only credentials in the `dc+sd-jwt` format can be requested.

= Extension Development

== Extend the Admin Console with the Declarative UI SPI (supported)
// https://github.com/keycloak/keycloak/issues/54149

Adding configuration screens to the Admin Console previously required maintaining a custom React theme for even simple provider forms.
The Declarative UI SPI lets extensions describe Admin Console pages and tabs in Java with `UiPageProvider` and `UiTabProvider`, and {project_name} renders those forms automatically.

In this release, the `declarative-ui` feature is promoted from experimental to supported and is enabled by default.

For more details, see the link:{ui_customization_guide_link}declarative-ui[Extending the Admin Console with the Declarative UI SPI] guide.
