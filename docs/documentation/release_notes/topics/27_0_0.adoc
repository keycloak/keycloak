= Administration

== Service account user ID available on client representation

The service account user ID is now included directly in the client representation as the `serviceAccountUserId` field.
This removes the need for a separate API call to discover the service account user, simplifying client administration and role mapping workflows.
The dedicated `GET /admin/realms/\{realm}/clients/\{id}/service-account-user` endpoint has been removed.
See the upgrading guide for migration details.

= Security and Standards

== SAML OneTimeUse condition enforced for identity brokering

When an external SAML identity provider issues an assertion with a `OneTimeUse` condition, {project_name} now rejects any later attempt to present the same assertion, as required by the SAML 2.0 specification.
This protects brokered logins against assertion replay, in particular in IdP-initiated flows where no `InResponseTo` binding is available.
How long a consumed assertion is remembered is bounded by the new *OneTimeUse maximum age* setting of the SAML identity provider, which defaults to 1 hour.
See the upgrading guide for details.

== Credential ID in credential update events

The `UPDATE_CREDENTIAL` events emitted by built-in required actions now carry the `credential_id` detail when a credential was created or updated in the {project_name} credential store, as the `REMOVE_CREDENTIAL` event already did. The detail is omitted when an external user-storage provider handles the update because there is no {project_name} credential ID to report.

== Token request parameters for OpenID Connect and OAuth 2.0 identity providers

OpenID Connect and OAuth 2.0 identity providers have a new *Token request parameters* setting. The configured name/value pairs are added to the authorization code exchange and the refresh token request that {project_name} sends to the token endpoint of the external identity provider.

For more information, see the link:{adminguide_link}#_identity_broker_oidc[OpenID Connect v1.0 identity providers] and link:{adminguide_link}#_identity_broker_oauth[OAuth v2 identity providers] sections in the {adminguide_name}.
