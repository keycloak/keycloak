== Breaking changes

Breaking changes are identified as those that might require changes for existing users to their configurations or applications.
In minor or patch releases, {project_name} will only introduce breaking changes to fix bugs.

=== X.509 authenticators process key usage and extended key usage validations correctly

The X.509 user authenticators (**X509/Validate Username Form** for browser authentication and **X509/Validate Username** for direct access grants) include two optional configuration settings for key usage and extended key usage. These settings allow administrators to validate the presence of specific purposes within the corresponding certificate extensions. Previously, validation only occurred if the extension was marked as critical in the certificate. Starting with this version, validation is performed regardless of the critical status.

Although the previous behavior was considered a bug, a new provider option is available for each authenticator to revert to the legacy validation if necessary.

[source,bash]
----
bin/kc.[sh|bat] start --spi-authenticator--auth-x509-client-username-form--legacy-critical-behavior true \
  --spi-authenticator--direct-grant-auth-x509-username--legacy-critical-behavior true
----

See link:{adminguide_link}#_x509[X.509 client certificate user authentication] for more information.

=== Kerberos username/password authenticator performs local service-ticket round trip

Previously, the Kerberos provider authenticated the user only against the KDC server by performing an AS-REQ/AS-REP exchange. Consequently, authentication could succeed against an unintended or rogue KDC if it was inadvertently selected. This applied only to direct Kerberos username and password authentication, never to browser-based SPNEGO/negotiate authentication.

Starting with this release, after authenticating the user, {project_name} performs an additional service-ticket round trip for its configured service principal. A service ticket is requested using TGS-REQ/TGS-REP and validated with the configured local keytab.

Although no issues are expected, the previous behavior can be restored with the following provider options for the LDAP and Kerberos standalone providers:

[source,bash]
----
bin/kc.[sh|bat] start --spi-storage--ldap--disable-kerberos-authentication-round-trip true \
  --spi-storage--kerberos--disable-kerberos-authentication-round-trip true
----
