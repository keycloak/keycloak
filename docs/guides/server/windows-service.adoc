This guide explains how to install and run {project_name} as a Windows service using Apache Commons Daemon.
Procrun runs `kc.bat start` as an external process in "exe" mode, preserving the script's augmentation and build logic.
The service uses system-wide environment variables, such as `KC_*`, and `conf/keycloak.conf`.
It does not inherit the environment variables of the user who installs the service.

==  Apache Commons Daemon Setup
To run {project_name} as a Windows service, you need the Apache Commons Daemon Procrun binary (`prunsrv.exe`).
Apache Commons Daemon 1.6.1 or later is recommended.
Download it for your platform: https://downloads.apache.org/commons/daemon/binaries/windows/

Then place `prunsrv.exe` into the Keycloak `bin` folder.

[source,bash]
----
copy "path\to\prunsrv.exe" "%KEYCLOAK_HOME%\bin\prunsrv.exe"
----

Use the amd64 binary for x86-64 systems or the ARM64 binary for Windows on ARM64.

== Optional: Pre-build

Pre-building is optional. If you do not pre-build, Keycloak will build automatically on first start, which takes longer.

[source,bash]
----
bin\kc.bat build --db=postgres
----

== Installing the Service

Keycloak includes a `tools windows-service` subcommand to simplify service installation and uninstallation.

Run service installation, uninstallation, start, and stop commands from an elevated terminal (Run as administrator).

[source,bash]
----
bin\kc.bat tools windows-service install --help
----

[source,bash]
----
bin\kc.bat tools windows-service uninstall --help
----

=== Examples

Install a basic service (runs as Local System by default):

[source,bash]
----
bin\kc.bat tools windows-service install --name keycloak
----

Manual startup with an explicit stop timeout:

[source,bash]
----
bin\kc.bat tools windows-service install --startup=manual --stop-timeout=60
----

Delayed auto-start:

[source,bash]
----
bin\kc.bat tools windows-service install --startup=delayed
----

Custom display name:

[source,bash]
----
bin\kc.bat tools windows-service install --name=my-keycloak --display-name="My Keycloak Server"
----

Use `--depends-on` to ensure required Windows services start before Keycloak (for example, a local database). By default Apache Commons Daemon may add `Tcpip` and `Afd` network dependencies.

[source,bash]
----
bin\kc.bat tools windows-service install --depends-on="postgresql-x64-15;Tcpip;Afd"
----

By default, the service runs as the Local System account, so `--service-user` and `--service-password` can be omitted.
To run as a specific user, the account must have the "Log on as a service" right.

[source,bash]
----
bin\kc.bat tools windows-service install --service-user="DOMAIN\Username" --service-password="password"
----

You can supply the service password through an environment variable instead of including it in the installation command line:

[source,bash]
----
set KC_SERVICE_PASSWORD=s3cret
bin\kc.bat tools windows-service install --service-user="DOMAIN\Username"
----

Start the service:

[source,bash]
----
net start keycloak
----

Stop the service:

[source,bash]
----
net stop keycloak
----

Stopping the service requests an orderly shutdown of {project_name}, including leaving the cache cluster and completing HTTP requests according to the configured shutdown timeouts.
If the stop request is received before {project_name} bootstrap begins, startup is cancelled and initialized resources are released instead.
Requests received later follow normal shutdown once runtime startup completes.
The `--stop-timeout` installation option limits the total time Procrun waits for its stop command and the server process to exit (60 seconds by default).
This includes starting the stop command's JVM and waiting for the shutdown event if the server is still starting.
If you configure `shutdown-delay` or `shutdown-timeout`, make `--stop-timeout` longer than their combined duration, with additional time for the stop command and other shutdown work.
If this timeout expires, Procrun forcefully terminates the process tree.

After upgrading, existing services configured to run `kc.bat stop` must be uninstalled and reinstalled to use the updated stop command.
Record any custom service installation options before uninstalling.

Uninstall the service (Procrun stops it first if it is running):

[source,bash]
----
bin\kc.bat tools windows-service uninstall --name keycloak
----

Check status using the Windows Services console (`services.msc`).

== Logging

When {project_name} runs as a service, it is recommended to enable file logging - see <@links.server id="logging"/>.

The service wrapper writes its logs (for example, `commons-daemon.YYYY-MM-DD.log`) to the directory containing the configured `log-file` at installation time.
Set `log-file` in `conf/keycloak.conf` or use the `KC_LOG_FILE` environment variable when installing the service.
If no custom `log-file` is configured, wrapper logs are stored in `<KEYCLOAK_HOME>\data\log`.

== Configuration Changes

To change runtime configuration:

1. Stop the service: `net stop keycloak`.
2. Update environment variables or `conf/keycloak.conf`.
3. Optionally re-run build: `bin\kc.bat build [new-options]`.
4. Start the service: `net start keycloak`.

== Troubleshooting

=== Access Denied errors

* Ensure the service runs as Local System (default) or that the specified account has "Log on as a service".

=== Options defined as environment variables are ignored

Windows Services run in a separate session (usually as the LocalSystem account) and do not inherit the environment variables of the user who created the service. Define the required `KC_*` environment variables as system-wide environment variables, so they are available to the service.

=== Forcefully terminate the service

If the Apache Commons Daemon wrapper becomes unresponsive:

[source,bash]
----
taskkill /f /im prunsrv.exe
----

Use caution — this will affect all Procrun-managed services on the host.

== Apache Commons Daemon configuration under the hood

When you create the service, the following Apache Commons Daemon Procrun settings are applied:

* StartMode: `exe` (runs `kc.bat` as an external process)
* StartImage: `<KEYCLOAK_HOME>\bin\kc.bat`
* StartParams: `start`
* StopMode: `exe`
* StopImage: `<KEYCLOAK_HOME>\bin\kc.bat`
* StopParams: `tools;windows-service;stop`
* StopTimeout: configurable (default: 60 seconds; `0` also uses Procrun's default of 60 seconds)

The installer also assigns an internal service ID through Procrun's `Environment` setting.
The server creates a Windows event for this ID before runtime initialization, using the service account's default access permissions.
{project_name}'s internal stop command, invoked by Procrun, waits for this event to be created and signals it under the same account.

Service configuration is stored in the Windows Registry under:

----
HKEY_LOCAL_MACHINE\SOFTWARE\WOW6432Node\Apache Software Foundation\ProcRun 2.0\<ServiceName>
----
