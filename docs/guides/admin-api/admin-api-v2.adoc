== Prerequisites

The Admin API v2 requires the `client-admin-api:v2` feature:

<@kc.start parameters="--features=client-admin-api:v2"/>

== Client Setup

=== Java

Add the dependency to your project:

[source,xml]
----
<dependency>
    <groupId>org.keycloak</groupId>
    <artifactId>keycloak-admin-client</artifactId>
</dependency>
----

[source,java]
----
import org.keycloak.admin.client.Keycloak;

Keycloak adminClient = Keycloak.getInstance("http://localhost:8080", "master", "admin", "password", "admin-cli");
----

=== JavaScript

[source,bash]
----
npm install @keycloak/keycloak-admin-client
----

[source,javascript]
----
import KcAdminClient from "@keycloak/keycloak-admin-client";

const kcAdminClient = new KcAdminClient({ baseUrl: "http://localhost:8080", enableExperimentalApis: true });
await kcAdminClient.auth({ username: "admin", password: "admin", grantType: "password", clientId: "admin-cli" });
----

=== CLI

The Admin API v2 uses the same CLI tool described in the {adminguide_link}#admin-cli[{adminguide_name}] with the `--v2` flag:

<@kc.admin parameters="--v2 config credentials --server http://localhost:8080 --realm master --user admin"/>

== Update Semantics (PUT vs PATCH)

The Admin API v2 separates full resource replacement from partial updates:

* *Replace (`PUT`)*: Replaces the entire resource configuration with the representation provided in the request body.
`PUT` does not preserve previous state for omitted fields.
Any omitted field or field set to `null` is resolved to its default schema value (or removed if it has no default).
* *Partial Update (`PATCH`)*: Modifies only the fields explicitly provided in the request body.
Omitted fields retain their current persisted values.
Setting a field with a schema default explicitly to `null` resets it to its default value, while setting optional fields without a schema default to `null` removes the stored configuration.
